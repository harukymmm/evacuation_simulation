# Connection（社会的相互作用）仕様書

## 概要

本モジュールは、避難シミュレーションにおけるエージェント間の社会的相互作用を定義する。4つの主要なアクション（SEARCH_FAMILY、TALK、CONTACT、FOLLOW）により、エージェントは家族探索・他者との情報交換・連絡・追従行動を実現する。

---

## 1. SEARCH_FAMILY（家族探索）

### 1.1 機能概要

エージェントが家族メンバーの想定位置に向かって移動するアクション。家族がいる可能性の高い場所（自宅、学校、職場など）を目指して移動する。

### 1.2 処理フロー

```text
エージェント
    ↓ LLMがSEARCH_FAMILYを選択
    ↓
シーン内家族のフィルタリング
    ↓ exists_in_scene=true かつ agent_id > 0 の家族のみが対象
    ↓ 対象となる家族がいない場合はEVACUATEにフォールバック
    ↓
探索対象の決定
    ↓ target_family_memberが指定されている場合
    │   → 名前で一致を試みる（シーン内家族のみ）
    │   → 見つからなければ続柄で一致を試みる
    ↓ 指定がない、または見つからない場合
    │   → 子供を優先（息子、娘）
    │   → 次に配偶者（妻、夫）
    │   → その他の家族
    ↓
目標位置の決定
    ↓ 相手の現在座標を取得（リアルタイム追跡）
    ↓ 10秒間隔で座標を更新
    ↓
移動開始
    ↓ NavMeshAgentで目標位置に向かう
    ↓ 定期的なLLM再評価で行動変更可能
```

**重要**: シーン外の家族（`exists_in_scene=false`または`agent_id=-1`）は探索対象外。シーン外家族はシミュレーション内に実体として存在しないため、座標を取得できない。

### 1.3 家族メンバー情報

各家族メンバーについて以下の情報が管理される：

| フィールド | 説明 |
|-----------|------|
| agent_id | シーン内に存在する場合は正の値、存在しない場合は-1 |
| name | 家族の名前 |
| relation | 続柄（妻、夫、息子、娘、父、母など） |
| spawn_category | スポーンする建物カテゴリ（Residential, Office, Schoolなど） |
| search_position | 探索する座標（スポーン時に設定） |
| likely_location | 想定される場所の説明（「住宅（○○アパート）」など） |
| has_phone | 連絡手段（スマートフォン）を持っているか |
| exists_in_scene | シミュレーション内に実在するか |
| distance_meters | 現在地からの距離 |
| is_reunited | 合流済みかどうか |

### 1.4 探索モード

SEARCH_FAMILYはシーン内家族のみを対象とし、リアルタイム追跡モードで動作する：

| 条件 | 動作 |
|------|------|
| `exists_in_scene=true && agent_id > 0` | リアルタイム追跡（10秒間隔で座標更新） |
| `exists_in_scene=false` または `agent_id=-1` | 探索対象外（EVACUATEにフォールバック） |

### 1.6 パラメータ

| パラメータ | 値 | 説明 |
|-----------|-----|------|
| 座標更新間隔 | 10秒 | シーン内家族の座標を更新する間隔 |
| 合流判定距離 | 10m | この距離以内で「合流」と判定しFOLLOWに移行 |

### 1.7 利用可能条件

SEARCH_FAMILYは以下の条件を満たす場合にのみ実行可能：

- 家族メンバーが存在する（一人暮らしでない）
- **シーン内に存在する家族が1人以上いる**（`exists_in_scene=true && agent_id > 0`）

シーン外の家族のみしかいない場合、SEARCH_FAMILYを選択してもEVACUATEにフォールバックする。

### 1.8 行動の継続と終了

- **継続**: 目標位置に向かって移動を継続
- **終了条件**:
  - LLMの定期再評価（デフォルト120秒間隔）で別の行動が選択される
  - 家族と合流した場合（10m以内）→ 自動的にFOLLOWに移行

### 1.9 LLM連携

#### リクエスト時に送信される家族情報

```
- 名前
- 続柄
- 想定される場所
- 探索座標
- 現在地からの距離
- 連絡手段の有無
- シーン内に実在するか
```

#### LLMレスポンス

```
- action_type: "SEARCH_FAMILY"
- target_family_member: 探索対象の名前または続柄
- reasoning: 行動理由
- confidence: 確信度
```

### 1.10 エラーハンドリング

| エラー状況 | 対処 |
|-----------|------|
| 家族情報がない | EVACUATEにフォールバック |
| シーン内家族がいない | EVACUATEにフォールバック |
| 探索対象のEvacueeが見つからない | EVACUATEにフォールバック |

### 1.11 合流処理

シーン内家族との距離が10m以内になった場合、以下の処理を実行：

1. SEARCH_FAMILYを終了
2. **双方の合流フラグを設定**
   - 探索者の家族データ: 対象家族の`is_reunited`を`true`に設定
   - 家族側の家族データ: 探索者の`is_reunited`を`true`に設定
3. 探索者が家族をFOLLOW対象に設定
4. 家族のFollowerリストに探索者を登録
5. 連帯行動を開始（家族の行動に追従）

#### LLMプロンプトへの反映

合流済みの家族は、LLMへのプロンプトで以下のように表示される：

```
【あなたの家族情報】
- 妻: 山田 花子（★合流済み★、距離: 約5m、連絡可能）
- 息子: 山田 太郎（小学校にいる可能性、距離: 約500m、連絡可能）

※ 山田 花子とは既に合流しています。一緒に行動してください。
※ まだ合流していない家族の安全も考慮して行動を選択してください。
```

| 家族の行動 | 探索者の動作 |
|-----------|-------------|
| EVACUATE | 同じ避難所を目指す |
| その他 | 家族の位置を追従 |

### 1.12 注意事項

- **シーン外家族（`exists_in_scene=false`または`agent_id=-1`）はSEARCH_FAMILYの対象外**
- シーン外家族はシミュレーション内に実体がないため、座標取得・合流が不可能
- LLMプロンプトでは「この地域外にいる家族（探索・連絡の対象外）」として別枠で表示

## 2. TALK（会話）

### 2.1 機能概要

エージェントが周辺の他のエージェントに話しかけ、情報交換や相談を行うアクション。避難所情報の共有、現状確認、行動相談などを目的とする。

### 2.2 処理フロー

#### 基本的な1往復フロー

```text
発話者                                  応答者
   │                                      │
   │ ExecuteTalkAction()                  │
   │ NavAgent停止                         │
   │                                      │
   │ ── [ラグ 5秒] ─────────────────────> │
   │                                      │
   │ OnConversationReceived()             │
   │                                      │ 応答拒否チェック
   │                                      │ NavAgent停止
   │                                      │ LLM応答生成
   │                                      │
   │ <───────────────────── [ラグ 5秒] ── │
   │                                      │
   │ OnConversationResponseReceived()     │
   │ 継続判定                              │ 会話履歴に追加
   │                                      │

※ TALK往復で約10秒（シミュレーション時間）のラグが発生
```

#### マルチターン会話フロー

1セッション内で最大10ターンまでの会話が可能。どちらかが`want_to_continue=false`を返した時点で会話終了。

```text
発話者                                  応答者
   │                                      │
   │ ───────── ターン1 ──────────────────> │
   │ <──────── want_to_continue=true ──── │
   │                                      │
   │ ───────── ターン2 ──────────────────> │
   │ <──────── want_to_continue=true ──── │
   │                                      │
   │ ───────── ターン3 ──────────────────> │
   │ <──────── want_to_continue=false ─── │ ← 応答者が終了希望
   │                                      │
   │ 会話セッション終了                     │
   │ RequestLLMDecision()                 │ RequestLLMDecision()
```

#### 会話終了条件

| 条件 | 説明 |
|------|------|
| 応答者が`want_to_continue=false` | 応答者が会話終了を希望 |
| 発話者が`want_to_continue=false` | 発話者が会話終了を希望（次のメッセージ送信時） |
| ターン上限到達 | 10ターンに達した場合、自動終了 |

**重要**: 発話者・応答者ともに会話中は立ち止まり、会話終了後にLLMで次の行動を決定する。

### 2.3 会話トピック

| トピック | 説明 |
|----------|------|
| ShelterInfo | 避難所の場所や状況に関する情報交換 |
| CurrentSituation | 現在の状況確認 |
| ActionAdvice | 行動に関する相談・助言 |
| SafetyConfirm | 安全性の確認 |
| General | 一般的な会話 |

### 2.4 パラメータ

| パラメータ | 値 | 説明 |
|-----------|-----|------|
| メッセージラグ | 5秒（シミュレーション時間） | 発話・応答それぞれにかかる時間 |
| 応答タイムアウト | 10秒（シミュレーション時間） | 応答を待機する最大時間 |
| 連続選択制限 | 5回 | 連続してTALK行動を選択できる最大回数 |
| セッション内ターン上限 | 10ターン | 1回の会話セッションでの最大往復回数 |
| 会話履歴保持数 | 5件 | 記憶される直近の会話履歴（短期記憶） |
| 周辺検索人数 | 最大5人 | LLMに送信される周辺避難者情報の上限 |

### 2.5 LLM連携

- **発話者**: LLMが会話対象・トピック・メッセージ内容を決定
- **応答者**: LLMが応答内容と情報共有の意思を生成
- **フォールバック**: LLM失敗時はトピックに基づくデフォルト応答を使用

### 2.6 記録される情報

会話履歴として以下の情報が保存される：
- 会話時刻
- 会話相手の識別子・名前
- 話題
- 自分のメッセージ
- 相手の返答
- 自分から話しかけたかどうか

## 3. CONTACT（家族連絡）

### 3.1 機能概要

エージェントが家族メンバーに連絡を取り、安否確認や情報交換を行うアクション。連絡対象がシミュレーション内に存在するか否かで処理が分岐する。

### 3.2 処理フロー

```text
送信者
    ↓
連絡対象の決定
    ↓ contact_targetが指定されている場合
    │   → 名前で一致を試みる
    │   → 見つからなければ続柄で一致を試みる
    ↓ 指定がない、または見つからない場合
    │   → 連絡手段あり（has_phone=true）の家族を優先
    ↓
連絡先の判定
    ↓ シーン内家族（exists_in_scene=true, agent_id > 0）
    │   → 相手のEvacueeに直接連絡
    ↓ シーン外家族（exists_in_scene=false, agent_id=-1）
    │   → サーバー経由でLLM応答を生成
```

#### シーン内家族への連絡フロー

```text
送信者                                  家族エージェント
   │                                      │
   │ ExecuteContactAction()               │
   │ NavAgent停止                         │
   │                                      │
   │ ── [ラグ 3秒] ─────────────────────> │
   │                                      │
   │ OnFamilyContactReceived()            │
   │                                      │ 応答拒否チェック
   │                                      │ NavAgent停止
   │                                      │ LLM応答生成
   │                                      │
   │ <───────────────────── [ラグ 3秒] ── │
   │                                      │
   │ OnFamilyContactResponseReceived()    │
   │ 継続判定                              │

※ CONTACT往復で約6秒（シミュレーション時間）のラグが発生
```

#### マルチターン連絡フロー

1セッション内で最大10ターンまでのやり取りが可能。どちらかが`want_to_continue=false`を返した時点で連絡終了。

```text
送信者                                  家族エージェント
   │                                      │
   │ ───────── ターン1 ──────────────────> │
   │ <──────── want_to_continue=true ──── │
   │                                      │
   │ ───────── ターン2 ──────────────────> │
   │ <──────── want_to_continue=false ─── │ ← 家族が終了希望
   │                                      │
   │ 連絡セッション終了                     │
   │ RequestLLMDecision()                 │ RequestLLMDecision()
```

**重要**: 送信者・家族エージェントともに連絡中は立ち止まり、連絡終了後にLLMで次の行動を決定する。

#### シーン外家族への連絡フロー

```text
連絡送信者
    ↓ [ラグ 3秒] 連絡開始
    ↓ サーバーにリクエスト送信
サーバー
    ↓ 家族のペルソナを用いてLLMで応答を生成
    ↓ 応答を返信
送信者が応答を受信
    ↓ RequestLLMDecision()
```

シーン外家族への連絡はサーバー側でLLM応答を生成するため、マルチターン会話は1往復で終了する（`want_to_continue=false`固定）。

### 3.3 連絡内容

#### 送信情報
- 送信者の識別子・名前・続柄
- メッセージ内容
- 現在の行動・目標避難所
- 現在位置の説明

#### 応答情報
- 応答者の識別子・名前
- 返信メッセージ
- 現在の状態（無事、軽傷、重傷など）
- 現在位置の説明
- 今後の行動予定

### 3.4 パラメータ

| パラメータ | 値 | 説明 |
|-----------|-----|------|
| メッセージラグ | 3秒（シミュレーション時間） | 送信・応答それぞれにかかる時間 |
| 応答タイムアウト | 15秒（シミュレーション時間） | 応答を待機する最大時間 |
| 連続選択制限 | 5回 | 連続してCONTACT行動を選択できる最大回数 |
| セッション内ターン上限 | 10ターン | 1回の連絡セッションでの最大往復回数 |

### 3.5 続柄の相互変換

連絡を受けた側が自分の続柄を推定する際の変換規則：
- 妻 ↔ 夫
- 息子/娘 → 親
- 父/母 → 子ども
- 兄/弟/姉/妹 → 兄弟姉妹

### 3.6 利用可能条件

CONTACTは以下の条件を満たす場合にのみ実行可能：

- 家族メンバーが存在する（一人暮らしでない）
- 連絡手段（スマートフォン）を持っている家族がいる

### 3.7 LLM連携

- **送信者**: LLMが連絡対象・メッセージ内容を決定
- **シーン内家族**: 相手のEvacueeがLLMで応答を生成
- **シーン外家族**: サーバー側でペルソナに基づき応答を生成

### 3.8 エラーハンドリング

| エラー状況 | 対処 |
|-----------|------|
| 家族情報がない | EVACUATEにフォールバック |
| 対象が見つからない | EVACUATEにフォールバック |
| 連続回数超過 | 避難行動に強制切り替え |

## 4. FOLLOW（追従）

### 4.1 機能概要

エージェントが周辺の他のエージェントについて行くアクション。追従者と追従対象の双方向の依存関係を管理し、行動の同期を実現する。

### 4.2 処理フロー

```
追従者
    ↓ 追従対象を選択
    ↓ 追従対象に自身を登録
追従対象
    ↓ 行動変更時に全追従者に通知
追従者
    ↓ 通知を受けて行動を同期
```

### 4.3 追従動作

追従対象の行動に応じた追従者の動作：

| 追従対象の行動 | 追従者の動作 |
|---------------|-------------|
| 避難所へ移動 | 同じ避難所を目指す |
| その場で待機 | 同じように待機 |
| その他 | 追従対象の位置を追従 |
| 避難完了 | 同じ避難所に向かい、追従を終了 |
| 消失 | 自動的に避難行動に切り替え |

### 4.4 パラメータ

| パラメータ | 値 | 説明 |
|-----------|-----|------|
| 周辺検索半径 | 30m | 追従対象を探す範囲 |
| 追従距離 | 2m | 追従対象に近づく際の停止距離 |
| 追従チェック間隔 | 1秒 | 追従位置を更新する間隔 |

### 4.5 追従者管理

追従対象は以下の機能で追従者を管理する：

- **登録**: 追従者が追従を開始する際に登録
- **削除**: 追従者が追従を終了する際に削除
- **行動変更通知**: 追従対象の行動が変わった際に全追従者に通知
- **消失通知**: 追従対象が消えた際に全追従者に通知

### 4.6 LLM連携

- **追従開始**: LLMが追従対象を決定
- **行動変更検知**: LLMが新しい行動を判断（LLM無効時は自動同期）

## 5. 周辺避難者検出

### 5.1 検出方法

指定された検索半径内の全避難者を検出し、距離順にソートして返却する。

### 5.2 取得情報

各避難者について以下の情報を取得：

- 識別子
- 現在位置
- 距離（メートル）
- 現在の行動
- 目標避難所
- 名前・役割・年齢層

### 5.3 混雑度計算

検出された人数から混雑度を計算：

```text
混雑度 = (検出人数 / 検索範囲面積) × 100
```

単位は「100平方メートルあたりの人数」

## 6. 応答拒否ロジック

TALK中またはCONTACT中のエージェントは、他者からの会話・連絡を受け付けず、即座にデフォルト応答を返す。

### 6.1 拒否条件

| 応答者の現在行動 | 対応 |
|-----------------|------|
| TALK（会話中） | 「すみません、今ちょっと話し中で...」と即座に拒否 |
| CONTACT（連絡中） | 「すみません、今電話中で...」と即座に拒否 |
| その他（EVACUATE, STAY, SEARCH_FAMILY, FOLLOW） | 通常通り立ち止まって会話に応じる |

### 6.2 拒否時の挙動

- 拒否応答を即座に返す（ラグなし）
- 応答者は立ち止まらず、現在の行動を継続
- 発話者/送信者は拒否応答を受け取り、会話履歴に記録

## 7. 無限ループ防止機構

社会的行動の無限ループを防止するための制限：

| アクション | 制限 | 制限超過時の動作 |
|-----------|------|-----------------|
| TALK | 連続選択5回まで、セッション内10ターンまで | 避難行動に切り替え |
| CONTACT | 連続選択5回まで、セッション内10ターンまで | 避難行動に切り替え |
| FOLLOW | 追従対象の消失時 | 避難行動に切り替え |

### 7.1 連続選択制限とセッション内ターン上限の違い

| 制限 | 説明 |
|------|------|
| 連続選択制限（5回） | LLMの行動決定で連続してTALK/CONTACTが選択される回数の上限 |
| セッション内ターン上限（10ターン） | 1回の会話/連絡セッション内での往復回数の上限 |

- 1回のTALK選択で最大10往復の会話が可能
- 会話終了後にLLMが再度TALKを選択した場合、連続選択カウントが増加
- 連続選択が5回に達すると、強制的に避難行動に切り替え

## 8. エラーハンドリング

### 8.1 TALK

| エラー状況 | 対処 |
|-----------|------|
| LLM失敗 | トピックに基づくデフォルト応答を使用 |
| 対象が見つからない | 避難行動に切り替え |
| 応答タイムアウト | デフォルト応答を使用 |

### 8.2 CONTACT

| エラー状況 | 対処 |
|-----------|------|
| LLM失敗 | デフォルト応答を使用 |
| 対象が見つからない | 避難行動に切り替え |
| 連続回数超過 | 避難行動に強制切り替え |

### 8.3 FOLLOW

| エラー状況 | 対処 |
|-----------|------|
| 追従対象の消失 | 避難行動に切り替え |
| 追従対象の避難完了 | 同じ避難所に向かい、追従を終了 |

## 9. データ構造

### 9.1 会話関連

#### 会話リクエスト
```
- 発話者識別子
- 発話者名
- 話題
- メッセージ内容
- 発話者の現在行動
- 発話者の目標避難所
- ターン数（マルチターン時）
```

#### 会話応答
```
- 応答者識別子
- 応答者名
- 応答メッセージ
- 情報共有の意思
- 会話継続意思（want_to_continue）
```

#### 会話セッションコンテキスト
```
- 会話相手識別子
- 会話相手名
- 現在のターン数
- 話題
- 相手の継続意思
- セッション開始時刻
- 家族連絡フラグ
```

#### 会話継続判断リクエスト
```
- リクエスト識別子
- ペルソナ情報
- セッションコンテキスト
- 相手の最後のメッセージ
```

#### 会話継続判断レスポンス
```
- リクエスト識別子
- 継続意思（want_to_continue）
- メッセージ（次の発言または締めの言葉）
- 判断理由
```

### 9.2 家族連絡関連

#### 連絡リクエスト
```
- 送信者識別子
- 送信者名
- 送信者の続柄
- メッセージ内容
- 送信者の現在行動
- 送信者の目標避難所
- 送信者の現在位置説明
- ターン数（マルチターン時）
```

#### 連絡応答
```
- 応答者識別子
- 応答者名
- 応答メッセージ
- 現在の状態
- 現在位置説明
- 今後の行動予定
- 連絡継続意思（want_to_continue）
```

### 9.3 周辺避難者情報
```
- 識別子
- 現在位置
- 距離
- 現在の行動
- 目標避難所
- 名前
- 役割
- 年齢層
```
